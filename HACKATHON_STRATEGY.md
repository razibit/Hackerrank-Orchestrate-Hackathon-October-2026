# Competitive strategy

Maximize first-place probability through correctness, reliability, authentic ownership and defensible measurements. Ranking and hidden scores cannot be guaranteed. The source coverage gate is complete; the remaining architecture and policy choices must now be confirmed by implementation measurements.

1. Start with a small end-to-end slice: parse a request, resolve a time-valid subject, collect scoped evidence, reduce state, apply category policy and serialize one validated row. Keep unresolved cases explicit.
2. Preserve full evidence recall before ranking facts. CSV event order is not chronological, successful checks can still mean an enabled connector or restorable archive, and database, replica, JSON and log captures have different time and completeness scopes.
3. Optimize exact rows/steps/citations, not status alone. Labels stay in evaluation.
4. Use model interpretation only where language, screenshots or ambiguous evidence require it; deterministic code enforces identity constraints, evidence time, conditional policy and serialization. Meaningful bounded tools are preferable to ornamental calls.
5. Add independent reasoning fixtures before tuning to 32/32 samples. The public set has no NOT_APPLICABLE examples.
6. Run a checkpointed 518-case trial only after all format adapters and the vertical slice work. Measure extraction coverage, unresolved cases, runtime and cost early.
7. Compose judge-readable Markdown reports from measured results; preserve genuine logs/traces. Prepare to explain a difficult case, failed hypothesis and limitation.

| Improvement | Evidence-based value | Effort/risk and gate |
|---|---|---|
| Historical identifiers, replica scope, full recall | Explicitly evaluated and broken in reference code | High effort; temporal/drift fixtures |
| Category and conditional policy fidelity | case_12/tombstone counterexamples | Medium/high semantic risk; content-backed tests |
| Citation/state/order validation | Exact contract; existing reusable tests | Low/medium; zero structural errors |
| Cache and batch extraction | Shared 94-file evidence across cases | Medium; hash invalidation and usage measurement |
| Negative/multilingual intent | Explicit task, sample coverage gap | Medium; independent linguistic fixtures |
| Targeted second model | Possible extraction improvement | Variable; measured held-out error reduction required |
| Embeddings/graph DB/multi-agent ensemble | No demonstrated need yet | Defer until exact retrieval baseline fails measurably |
| UI or broad legal-compliance essay | No requirement identified | Defer |

General 30/30/30/10 weights support balanced artifacts. Historical subrubrics are guidance, not October guarantees. Do not optimize imagined hidden rules.

For each iteration record failure, hypothesis, smallest fix, before/after metrics, runtime/cost and regressions. Keep only supported improvements. Perfect public samples are a target, not proof of hidden performance. Never hardcode case IDs, screenshot verdicts or canonical sample steps.

Interview: explain authorization; future-alias prevention; replica conflict; source-specific categories; permitted tombstones; claims vs readbacks; exact ordering; actual usage and limits. Use Decision → Reason → Implementation → Evidence → Limitation. Do not reuse S4's unmeasured regression stories as personal experience.

Reserve a submission buffer after verifying the live cutoff. If time shrinks, prioritize a complete tested path and truthful artifacts. A fallback is not a constant-status CSV or copied labels.
